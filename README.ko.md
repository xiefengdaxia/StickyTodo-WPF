# StickyTodo

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | **한국어**

처음부터 직접 작성한 Windows 데스크톱 스티키 노트 / 할 일 앱: WPF + .NET 8 + SQLite. **모든 것이 로컬에서 동작**합니다 — 서버 접속 없음, 계정 없음, 텔레메트리 없음, 업데이트 확인 없음. **모든 사용자가 기본으로 평생 멤버이며 모든 기능이 무제한**입니다. UI는 **简体中文 / English / 日本語 / 한국어** 4개 언어를 지원하며 설정에서 언제든 전환할 수 있습니다.

> 유사 도구의 제품 형태(다중 보드, 보드당 창 하나, 반복 작업, 캘린더)는 참고했지만 **코드, UI, 문구, 색상은 모두 이 프로젝트의 독자 구현**입니다. 다른 프로그램의 디컴파일 산출물, 리소스 파일, 비공개 API는 전혀 복제하지 않았습니다.

## 0. 다운로드해서 바로 사용(포터블 버전)

.NET 런타임을 설치하고 싶지 않다면 포터블 버전을 받으세요:

**[⬇ 최신 StickyTodo-x.x.x-win-x64-portable.zip 다운로드](https://github.com/xiefengdaxia/StickyTodo-WPF/releases/latest)**

압축을 풀고 `StickyTodo.exe`를 더블클릭하면 끝. **.NET 8 런타임이 포함된 70MB 단일 exe, 의존성 없음**.

- 압축 파일에 `portable.marker`가 들어 있어 데이터(`sticky.db`와 로그)가 exe 옆 `data\` 폴더에 저장됩니다 —— **폴더째 복사하면 데이터도 함께 이동**하므로 USB 메모리에 적합
- `portable.marker`를 삭제하면 일반 모드(`%LOCALAPPDATA%\StickyTodo`)로 돌아갑니다
- 첫 실행 시 SmartScreen 경고가 나올 수 있습니다(서명 없음). 「추가 정보」→「그래도 실행」을 선택하세요
- 시스템 요구 사항은 아래 「실행 환경」 참조

**실행 환경**

| 항목 | 요구 사항 |
|---|---|
| OS | **Windows 10 1809(x64) 이상**, Windows 11 모든 버전 |
| CPU | **x64** (ARM64 기기는 x64 에뮬레이션으로 동작할 수 있으나 미검증) |
| .NET 런타임 | **불필요**(.NET 8 자체 포함) |
| 기타 의존성 | **없음**. WPF 그래픽 스택, SQLite 네이티브 라이브러리, VC++ 런타임 모두 내장 |
| 디스크 | 약 71MB(exe 자체), 데이터는 수 MB부터 |
| 권한 | 일반 사용자 권한으로 충분. **관리자 권한 불필요**(자동 시작은 HKCU만 기록) |

미지원: Windows 7/8/8.1(.NET 8과 WPF의 새 DPI API 미지원), 32비트 시스템, Linux/macOS.

**임시 폴더 관련**: 단일 파일 빌드는 첫 실행 시 네이티브 라이브러리(wpfgfx_cor3.dll, e_sqlite3.dll 등 약 10MB)를 %TEMP%\.net\StickyTodo\ 에 압축 해제합니다. 따라서 %TEMP%가 쓰기 가능해야 하며, 임시 폴더 정책이 매우 엄격한 환경에서는 실행되지 않습니다. 압축 해제를 피하려면 PublishSingleFile을 제거한 폴더형 자체 포함 게시를 사용하세요.

직접 빌드하려면:

```powershell
.\tools\publish-portable.ps1 -Version 1.0.0                    # 패키징만
.\tools\publish-portable.ps1 -Version 1.0.0 -CreateRelease     # 패키징 후 GitHub Release 게시
```

스크립트는 테스트 → 단일 파일 게시 → 포터블 마커 추가 → ZIP 생성 → **스모크 테스트**(`--portable-check`로 실제 프로세스를 띄워 데이터가 exe 옆에 생성되는지 확인) → 선택적 Release 업로드 순으로 실행합니다.

## 3. 현재 기능

**다국어(4개 언어)**
- UI는 **简体中文 / English / 日本語 / 한국어**를 지원하며 설정 화면의 언어 드롭다운에서 전환하고 **재시작 없이 즉시 적용**됩니다
- 전환 시 열려 있는 모든 창을 순회하며 변환기를 쓰는 바인딩을 다시 평가합니다(`LocalizationService.RefreshAllWindows`). 따라서 전환 직후 모든 문구가 바뀝니다
- 선택한 언어는 저장되고(`appearance.language`) 다음 실행 시 복원됩니다. 적용은 **어떤 창도 만들기 전**에 이루어지므로 중국어가 잠깐 보이는 일이 없습니다
- `--lang en|ja|ko|zh-CN`으로 해당 실행에만 언어를 강제할 수 있습니다(캡처 회귀용, 설정에 기록하지 않음)
- **음력 용어는 중국어 그대로 유지**: 음력 날짜, 간지, 건제십이신, 절기 이름, 길흉 항목 자체는 번역하지 않습니다(중국 역법 고유 개념이라 억지로 옮기면 의미가 통하지 않음). 다만 「음력」「절기」「길한 일」「흉한 일」같은 **레이블**은 UI 언어를 따릅니다
- 숫자 단위도 언어를 따릅니다: 중국어는 万/亿, 그 외 언어는 M/B
- 문구 일관성은 단위 테스트로 보장합니다: `LocalizationTests`가 4개 언어 존재, `{0}/{1}` 자리표시자의 언어 간 일치, 모든 번역문이 `string.Format`을 통과하는지 검증합니다

**모양(스티커 느낌)**
- **모든 창에 시스템 제목 표시줄이 없습니다**: 메인 창, 설정 창, 노트 창, 입력 대화상자 모두 직접 그린 제목 표시줄(드래그 가능, 메인/설정은 가장자리 크기 조절과 최대화 지원)
- 노트 창은 **테두리 없음 + 둥근 모서리 + 그림자**, 가장자리 8px 크기 조절(`WM_NCHITTEST` 직접 처리)
- **10가지 테마**: 클래식 옐로 / 페이퍼 화이트 / 민트 / 스카이 블루 / 바이올렛 / 사쿠라 핑크 / 애프리콧 / 그래파이트 나이트 / 미드나이트 잉크 / 에스프레소(어두운 테마 3종은 글자가 자동으로 밝아짐)
- **두 가지 불투명도를 따로 조절, 10% 단위 10단계**: 배경 불투명도 10–100%(종이만 투명해지고 글자는 항상 선명), 창 불투명도 10–100%(글자도 흐려짐)
- **투명해지는 것은 노트/메모 보드/캘린더뿐**이며 메인 창과 설정 창은 불투명 창입니다
- 직접 그린 컨트롤: 둥근 체크박스, 얇은 슬라이더, 평면 스크롤바, 세그먼트 전환, 카드, **우클릭 메뉴**(하위 메뉴 화살표, 체크 표시, 구분선, 색상은 테마 따름)
- 제목 표시줄 버튼: 📌 항상 위, 🔒 잠금, 🎨 테마 전환, ⋯ 메인 창, ✕ 닫기
- 노트는 작업 표시줄 자리를 차지하지 않습니다(스티커 스타일). 진입점은 트레이와 메인 창입니다

**설정 화면(독립 창)**
- **언어 드롭다운**: 4개 언어를 원어 이름으로 표시하고 선택 즉시 적용
- 10가지 테마를 **색상 카드 그리드**로 표시(2행 × 5개). 한 번 클릭하면 모든 창에 즉시 적용(재시작 불필요)
- 불투명도 슬라이더 2개, 실시간 미리보기와 즉시 저장
- 전역 단축키 3가지 목록
- 데이터 영역: 멤버십 상태, 콘텐츠 통계(보드/할 일/완료/태그 수), 로컬 저장 경로
- 진입점: 메인 창 왼쪽 아래 「설정」, 트레이 우클릭 메뉴 「설정」

**보드**
- 보드 하나에 창 하나, 여러 개를 동시에 열 수 있습니다. 이미 열린 보드를 다시 열면 기존 창이 활성화됩니다
- **4종 보드**: 할 일 보드(목록), 메모 보드(종이 한 장, 쓰면서 자동 저장), 캘린더 보드(월 보기), Token 사용량 보드
- 창 위치와 크기는 보드별로 기억되고(재시작 시 원위치), 모니터가 바뀌면 화면 안으로 되돌립니다
- **가장자리 스냅**: 화면 가장자리나 인접한 노트 창에 자동 정렬(종이 가장자리 기준, 그림자 여백 제외)
- 관리 패널: 할 일/메모/캘린더 보드 생성, 이름 바꾸기, 삭제, 더블클릭으로 열기, 종류와 할 일 개수 표시
- **카드 우클릭 메뉴**: 열기 / 이름 바꾸기… / 삭제(우클릭한 카드가 자동 선택됨)
- **창 전체를 드래그할 수 있습니다**(버튼, 목록 항목, 입력란, 스크롤바 제외). 비상호작용 영역 더블클릭으로 최대화/복원
- 트레이 아이콘: 보드 창별 체크식 표시 전환, 모두 표시/숨기기, 관리 패널 열기, 종료. ✕는 트레이로 숨기기만 함

**캘린더 보드**
- 월 보기는 6주 고정 그리드(월요일 시작). 오늘 강조, 주말 빨강, 월 밖 날짜 흐리게. 요일 머리글은 언어를 따름
- **각 칸에 음력 표시**(1일은 「X월」, 그 외는 「初二/廿三」 등)
- **절기 / 전통 명절 / 법정 공휴일**을 칸에 표시: 절기(입춘, 청명, 상강…), 제석, 춘절, 원소, 단오, 칠석, 중추, 중양, 납팔, 그리고 원단, 노동절, 국경절 등
- **「休」/「班」 배지**: 빨간 休는 휴일, 회색 班은 대체 근무일(데이터는 국무원 2024–2026년 휴일 공지를 직접 입력, 네트워크 없음)
- 일정이 있는 칸은 색 점과 제목 요약을 표시하고, 아래에 선택한 날짜의 일정 목록이 나옵니다
- **날짜를 클릭하면 길흉 표시**: 음력 날짜, 간지 연도/띠, 일 간지, 건제십이신, 그리고 **길한 일 / 흉한 일** 각 5개
- **연/월 드롭다운**: 임의의 연도(앞 60년/뒤 30년)와 월로 바로 이동하거나 ‹ › / 오늘로 이동. 월을 바꾸면 선택한 날짜도 그 달로 따라갑니다
- 캘린더에서 일정을 체크할 수 있고, 체크 후 자동 새로고침됩니다
- **일정을 다른 날짜 칸으로 드래그하면 일정 변경**(시각은 유지하고 날짜만 변경)
- 데이터는 **모든 보드**의 할 일에서 오며 반복 할 일은 규칙에 따라 여러 번 전개됩니다

**Token 사용량 보드**
- **데이터는 로컬 opencode 데이터베이스**(기본 `~/.local/share/opencode/opencode.db`, 설정에서 경로 변경 가능)에서 가져옵니다. **완전 오프라인**이며 읽기 전용으로 열고 다른 사람의 DB에 쓰지 않습니다
- `session_message`(v2) 한 테이블만 읽습니다. 이전 `message`(v1)는 내용이 모두 v2로 이전되었고 공식적으로 더 쓰지 않으므로 코드에서 완전히 무시합니다
- **범위 전환이 빠릅니다**: 큰 JSON은 행마다 한 번만 파싱(다중 경로 `json_extract`), 시간 조건은 가장 안쪽 `WHERE`로 밀어 넣고, SQL 한 개로 합계·추세·모델별을 동시에 계산합니다. 지난 날짜는 일 단위로 메모리에 캐시하고 "오늘"만 매번 다시 계산합니다
- **자동 새로고침 간격 5/15/30초** 선택 가능, ⟳로 수동 새로고침도 가능
- **집계 범위**: 오늘(시간 단위) / 최근 3일 / 최근 7일 / 최근 30일(7일 이상은 일 단위로 자동 집계)
- 상단 요약: 총 Token, 호출 수, 캐시 비율. 아래 줄에 입력/출력/추론/캐시 읽기를 나눠 표시
- **추세 그래프**: 누적 막대(입력/출력/추론/캐시 읽기/캐시 쓰기) + 꺾은선(호출 수). **막대나 꺾은선 점을 클릭하면 해당 시간대 상세를 표시**하며, 자동 새로고침이 열어 둔 상세를 지우지 않습니다
- **모델별**: 모델마다 Token 합계, 점유율, 호출 수와 세부 내역
- 실패는 바닥글에만 표시하고 모달을 띄우지 않습니다. 오프라인일 때는 직전 데이터를 유지합니다

**뽀모도로 타이머**
- 트레이 메뉴 「뽀모도로 타이머」로 열리는 독립 소형 창, 기본으로 항상 위
- 25분 집중 + 5분 짧은 휴식, **뽀모도로 4개마다 15분 긴 휴식**(사이클 수는 `PomodoroEngine`에서 설정 가능)
- 원형 진행률과 큰 카운트다운. **집중/휴식 색상 구분**, 원형은 30fps로 보간
- 시작/일시정지/계속/초기화/건너뛰기. 집중 종료 시 트레이 알림, 휴식 종료 시 다음 집중으로 자동 진행
- **오늘 완료 개수를 저장**하고 날짜가 바뀌면 자동으로 0이 됩니다

**할 일(표 형식 인라인 편집)**
- **「추가」 버튼도 체크박스도 없습니다**: 목록 끝에 항상 초안 행이 있습니다 — 「＋ 여기에 입력하고 Enter로 추가」
- **조작 버튼은 행에 마우스가 들어갈 때만 표시**되며 **행 끝 맨 오른쪽**에 고정되어 제목 공간을 차지하지 않습니다: 할 일 행은 `✓`(완료)와 `✕`(삭제), 완료 행은 `↺`(되돌리기)와 `✕`
- **둘째 줄의 배지와 태그 이름은 제목 왼쪽 끝에 정렬됩니다**
- **모든 행을 바로 편집할 수 있습니다**: 제목을 클릭해 편집, Enter로 확정 후 다음 행으로 이동, Tab이나 다른 곳 클릭도 자동 확정, Esc는 취소
  - 빈 제목은 거부되고 원래 값으로 돌아가며 행 안에 「내용을 입력해야 합니다」가 표시됩니다
  - 포커스된 행은 강조되고 입력란에 호박색 테두리가 생겨 다른 행을 잘못 고치지 않습니다
- **드래그 핸들**(각 행 왼쪽 세 점): 위아래로 드래그해 순서 변경, 위쪽 태그 칩에 드롭하면 그 태그 지정, 「전체/미분류」에 드롭하면 태그 해제
- **빈 곳을 클릭하면 편집 종료**: 입력란이 아닌 곳을 클릭하면 편집 중인 행을 확정하고 포커스를 해제합니다
- **TODO / Done 보기 전환**: 하단 세그먼트 버튼(`할 일 N` / `완료 N`)으로 한 번에 전환
  - 할 일 보기는 미완료만, 직접 드래그한 순서를 유지
  - Done 보기는 완료만 **완료 시간 내림차순**(최근 완료가 위)으로 표시하고 행마다 완료 시각 레이블을 붙입니다(오늘 14:41 / 어제 09:05 / 10월 18일 20:11 / 2025년 12월 30일 08:00)
  - Done 보기에서는 초안 입력란이 비활성화되어 "추가했는데 안 보이는" 상황을 막습니다
- **마감일(카운트다운)**: 우클릭으로 오늘/내일/이번 주말/사용자 지정 설정. 행에 「N일 남음 / 오늘 마감 / N일 지남」을 표시하고 지난 것은 빨간색
- **알림**: 우클릭으로 30분 후 / 1시간 후 / 오늘 18:00 / 내일 9:00 / 사용자 지정 설정. 시간이 되면 오른쪽 아래 소형 창 + 트레이 풍선 알림, 「10분 뒤 다시 알림」 가능. 20초 간격 폴링, 전부 로컬
- **반복 할 일(RFC 5545 RRULE)**: 우클릭으로 매일 / 평일마다 / 매주 / 2주마다 / 매월 / 매월 마지막 날 / 매년, 또는 사용자 RRULE(예 `FREQ=MONTHLY;BYDAY=2TU`) 입력
  - 체크해도 사라지지 않고 **완료 이력을 1건 기록하고 마감일을 다음 회차로 넘깁니다**(알림 시각도 함께 이동)
  - 행에 🔁 배지와 사람이 읽을 수 있는 설명 표시
- **드래그 정렬**(인덱스 대신 "특정 항목 앞으로 이동"을 사용하므로 태그로 필터링한 상태에서 드래그해도 어긋나지 않음)
- 우클릭 메뉴: 완료 상태 전환, 태그 지정/해제, 마감일 설정, 알림 설정, 반복 설정, 삭제

**태그**
- 전역 태그이며 할 일 하나에 여러 개를 붙일 수 있습니다. 필터 칩은 전체/미분류/각 태그이고 개수 표시가 붙습니다
- 태그 생성·이름 변경·삭제. 태그를 삭제해도 할 일 자체는 영향을 받지 않습니다

**전역 단축키**(다른 창에 포커스가 있어도 동작)
- `Ctrl+Alt+N` 새 할 일(기본 할 일 보드를 열고 입력란에 포커스)
- `Ctrl+Alt+H` 모든 노트 표시/숨기기
- `Ctrl+Alt+L` 현재 보드 잠금/해제
- 등록에 실패하면(다른 프로그램이 사용 중) 조용히 건너뛰고 실행에는 영향을 주지 않습니다

**모션(일관된 즉시 피드백)**
- **창 입장**: 위치가 정해진 뒤 페이드인 + 약간 확대(애니메이션 대상은 Window 자체가 아니라 내용. 반투명 창이 애니메이션 중 비트맵화되어 글자가 흐려지는 것을 막기 위함)
- **버튼**: 호버 시 하이라이트 레이어가 페이드인(색이 툭 바뀌지 않음), 누르면 4% 축소 후 되돌아옴. `Primary` / `Ghost` / 제목 표시줄 둥근 버튼 / 태그 칩 모두 적용
- **체크박스**: 체크 시 사각형이 1.18배로 커졌다 돌아오고 체크 표시가 40%에서 100%로 자랍니다(`BackEase`). 해제 시 역재생
- **슬라이더**: 손잡이가 호버 시 1.2배, 드래그 중 1.35배
- **할 일 행**: 호버 시 행 끝 버튼이 페이드인, `✓`에서 행이 펄스, `✕`에서는 행이 페이드아웃한 뒤 실제로 삭제, Enter로 추가한 행은 위에서 슬라이드인
- **태그 칩**: 선택 시 굵게·색 변경, 호버 시 하이라이트 그라데이션
- **목록 카드**(관리 패널): 호버 시 1.2% 확대
- **캘린더 칸**: 호버 시 4% 확대 + 강조, 날짜 클릭 시 아래 길흉 패널이 페이드인
- **알림 팝업**: 아래에서 슬라이드인 + 페이드인되어 놓치기 어렵습니다
- **Token 보드**: 가져오는 동안 새로고침 아이콘이 계속 회전. 첫 로딩에서만 버튼이 어두워지고 범위 전환 시 깜빡이지 않습니다
- **뽀모도로**: 진행 원형을 30fps로 보간해 250ms마다 튀지 않고 흐르듯 움직입니다
- **OS 설정 존중**: Windows 「접근성 → 시각 효과 → 애니메이션 효과」를 끄면 모든 모션이 생략됩니다(`Motion.Enabled`가 `SystemParameters.ClientAreaAnimation`을 읽음)

- 데이터베이스 자동 마이그레이션(`PRAGMA user_version`, v1→v4 구현)

## 4. 데이터 모델

```sql
board(id, name, sort, is_default, kind, created_at,
      win_left, win_top, win_width, win_height)          -- kind: todo | memo | calendar | token
todo(id, board_id→board.id ON DELETE CASCADE, title, note,
     is_done, done_at, due_at, remind_at, reminded_at, recurrence,
     sort, created_at, updated_at)                        -- recurrence: RFC5545 RRULE
todo_completion(id, todo_id→todo.id, occurrence_at, completed_at)
tag(id, name UNIQUE COLLATE NOCASE, color, sort, created_at)
todo_tag(todo_id→todo.id, tag_id→tag.id, PRIMARY KEY(todo_id, tag_id))
note(id, board_id→board.id UNIQUE, content, created_at, updated_at)
setting(key PRIMARY KEY, value)
```

설계 포인트:

- **모든 시각은 Unix 초(INTEGER)로 저장**하고 읽을 때 `.ToLocalTime()`으로 로컬 시각으로 되돌립니다(그렇게 하지 않으면 알림 시각이 시간대만큼 어긋납니다. 실제로 겪고 고친 버그입니다). `DateTimeOffset`은 저장소 경계에서만 변환합니다.
- **논리 외래 키 + 캐스케이드 삭제**: 모든 연결에서 `Foreign Keys=True`를 켜므로 보드를 삭제하면 할 일이 지워지고 태그를 삭제하면 연결이 지워집니다.
- **WAL 모드**(`journal_mode=WAL`, `synchronous=NORMAL`)로 여러 창의 동시 읽기가 더 안정적입니다.
- **마이그레이션은 `PRAGMA user_version`을 증가**시키는 방식이고 `Initialize()`는 멱등입니다. `SchemaMigrationTests`가 실제 v1 DB를 자동 업그레이드하고 데이터가 유실되지 않는지 검증합니다.
- 저장소는 짧은 연결 + 연결 풀을 쓰고 긴 연결을 유지하지 않아 여러 창과 백그라운드 스레드 간 경쟁을 피합니다.

## 5. 완전 로컬(검증 가능하며 구호가 아님)

- Token 사용량 보드가 읽는 것은 **로컬 opencode SQLite 데이터베이스**이며 로컬 파일 읽기입니다. 마찬가지로 네트워크를 쓰지 않고 아무것도 전송하지 않습니다.
- 계정 체계, 클라우드 동기화, 텔레메트리, 버전 확인이 없습니다.
- 호스트는 의도적으로 `Host.CreateDefaultBuilder()` 대신 `new HostBuilder()`를 사용합니다. 전자는 `appsettings.json`, 환경 변수, 명령줄 구성을 읽어 들이지만 여기서는 구성 소스를 모두 닫았고 동작은 오직 코드로만 결정됩니다.
- 실행 가능한 보장: `tests/StickyTodo.Tests/NoNetworkTests.cs`가 **Core와 Infrastructure 어셈블리의 참조 목록에** `System.Net.Http` / `System.Net.Sockets` / `System.Net.Requests` / `System.Net.WebClient` **가 없음**을 단언합니다. 누군가 이 두 계층에 네트워크 의존을 다시 넣으면 테스트가 즉시 실패합니다.

## 6. 멤버십 전략(중요)

배포판은 `PermanentFreeEntitlement`를 등록합니다:

```csharp
// src/StickyTodo.App/App.xaml.cs
services.AddSingleton<IEntitlementService, PermanentFreeEntitlement>();
```

`PermanentFreeEntitlement`는 모든 상한이 `int.MaxValue`, `IsPro = true`, `Tier = Lifetime`이므로:

- UI의 멤버십 배지, 권한 판정, 할당량 검사 **로직이 모두 남아 있고 정상 동작**합니다(판정을 지운 것이 아닙니다);
- 사용자 입장에서는 평생 무료이고 기능 제한이 없습니다;
- 나중에 유료화하려면 `FreeTierEntitlement`(구현 완료: 보드 2 / 태그 3 / 반복 규칙 5 / ICS 미포함)로 바꾸거나 「로컬 라이선스 파일에서 등급을 읽는」 구현을 추가하면 되고, **비즈니스와 UI 코드는 한 줄도 바꿀 필요가 없습니다**.

할당량 판정은 `TodoService` 계층에만 두고, UI는 `EntitlementLimitException`을 표시하기만 합니다.

## 8. 알려진 제한

- 제목 표시줄 커스텀 스킨은 없습니다. 노트는 직접 그린 표시줄을 쓰고 메인 창과 설정 창도 직접 그리므로 드래그와 스냅이 여기에 의존합니다. 변경할 때는 조작감을 먼저 고려하세요.
- 스냅은 창 외곽으로 계산하므로 DPI가 다른 모니터 사이에서는 근사값입니다.
- 태그 필터는 단일 선택 칩이며, 두 태그를 동시에 거르는 기능은 아직 없습니다.
- 캘린더는 월 보기만 지원합니다. 반복 규칙은 「이번만 건너뛰기」와 「한 회차만 편집」을 지원하지 않습니다(편집하면 규칙 전체가 바뀝니다).
- **공휴일·대체 근무일 데이터는 직접 입력**한 것입니다(2024–2026년 수록). 국무원이 매년 11월경 다음 해 일정을 발표하므로 그때 `ChineseHolidays`에 데이터를 추가해야 합니다. 범위를 벗어난 연도는 「주말은 휴무」라는 기본 판정만 적용됩니다.
- **24절기는 일반 일수 계산식으로 구합니다**, 따라서 연도에 따라 공식 역서와 하루 차이가 날 수 있습니다(식 안의 예외 표가 알려진 편차를 보정).
- **길흉의 길한 일/흉한 일은 건제십이신에서 도출한 일반 항목**이며 날짜별 역주가 아닙니다. 참고용이고 날짜 선택, 신살, 시각 길흉은 다루지 않습니다.
- **중국어가 아닌 UI에서는 음력 내용이 중국어로 표시됩니다**: 의도적인 절충입니다(위 「다국어」 참조). 완전히 현지화하려면 `UiStrings`에 번역을 추가하고 `Almanac`의 항목도 리소스로 만드세요.
- **Token 보드는 opencode의 테이블 구조에 의존**합니다(`session_message.data`의 `tokens` / `model` 필드). opencode 개편으로 필드가 바뀌면 수치가 0이 되므로 SQL을 조정해야 합니다. DB가 없으면 바닥글이 설정에서 경로를 지정하라고 안내합니다.
- Token 보드에서 큰 범위를 **처음** 열 때(최근 30일은 100MB 이상 읽음)는 1초 정도 걸립니다. 같은 범위는 그다음부터 밀리초 단위입니다. 지난 날짜 캐시는 메모리에만 있으므로 프로그램을 재시작한 뒤 첫 진입은 다시 계산합니다.
- Token 통계는 **메시지 단위 사용량 누적**이며, opencode가 세션 단위로 누적하는 `session_v2.tokens_*`와 집계 기준이 조금 다를 수 있습니다(메시지 단위가 더 세밀하고 시간별 버킷팅에 유리).
- 반복 할 일의 완료 이력은 기록만 하고 아직 표시하지 않습니다(향후 「이번 달 몇 회 완료」 같은 통계에 사용).
- UI 계층에는 자동 테스트가 없고 `--selftest` / `--recurrence-demo` / `--shot` 등 12개 회귀 모드로 보장합니다.
